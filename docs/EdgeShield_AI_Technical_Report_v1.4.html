1. Dual-Pipeline Arm SoC Architecture

Architectural Safety Boundary — Detectors Decide, Llama Explains: Pipeline A runs three dedicated deep-learning classifiers simultaneously on RK3588 NPU Cores 0, 1, and 2. Pipeline B runs quantized Llama-3.2-1B (766 MB, max_context_len=512, 8da4w + 4-bit embeddings) strictly on Arm64 CPU via ExecuTorch (XNNPACK + Arm KleidiAI) behind a prompt-injection sanitizer and verdict-locked validator. Llama never alters risk verdicts or SCI policies.

4. Safety Controls, Governance & Honest Limitations

  • Verdict-Locked Advisory & Bilingual UX: Prompt-injection sanitization, anti-contradiction checks, hallucinated-phone filtering, repetition-loop stops, EN/Hindi (1930 helpline) safety guidance, and offline browser Read-Aloud TTS.
  • Reversible Containment Ladder: Dry-run by default (EDGESHIELD_CONTAINMENT_DRY_RUN=true), auto-protects local/gateway/DNS hosts, finite TTLs + one-click Undo logged to the SHA-256 SCI ledger, plus optional X-EdgeShield-Token auth and opt-in SSRF-safe Link Sandbox (disabled in offline mode).
  • Known Limitations: (1) Passive AF_PACKET does not decrypt TLS/DoH payloads. (2) Compromised clean domains require enabling the opt-in Link Sandbox. (3) The deployed ctx=512 766 MB .pte (8da4w + 4-bit embeddings, 918.8 MB RSS) is exported from the local Llama-3.2-1B base checkpoint, so Hindi mode pairs live Hinglish explanations with full Devanagari vetted recommendations (swapping an Instruct Hindi checkpoint via scripts/export_llama_executorch.sh requires zero C++ changes). (4) Cellular phone SMS reaches the gateway via the included Termux/webhook LAN companion. (5) Conservative red-team thresholds yielded 4/31 benign FPs on synthetic controls, remediable via 9-stage SCI closed-loop allowlisting.
